## 현재 결정

Upstream Scout는 추적 중인 공개 스킬·워크플로우 소스의 **의미 있는 변화만** 감지해 사용자에게 검토할 내용을 제시한다. 버전 소스는 minor 이상, 비버전 소스는 실제 사상이나 기능 변화가 있을 때만 본조사를 시작한다. 주기가 왔다는 이유만으로 본조사를 시작하지 않는다.

소스마다 마지막 리뷰 지점 이후의 사실, 사상 이동, 이 프로토콜과의 접점, 가치 높은 후보를 수집한다. 현재 프로토콜이 기본값이며 변경 제안은 놓친 맥락과 그대로 둘 비용을 입증해야 한다.

관련 후보는 함께 볼 때 비교와 판단이 좋아지면 한 묶음으로 리뷰한다. 한 후보씩이라는 고정 리듬은 P-0022의 Align 질문 묶음 원칙과 사용자 피드백에 맞춰 제거했다.

검토는 같은 세션의 대화에서 끝내고, 맥락이 이동할 때만 프로토콜의 일반 작업 계약을 쓴다. 사용자 리뷰에서 채택·기각을 정한 뒤 프로토콜 변경 이력, 해당 skill rationale, `upstream-sources.md`에 결론을 직접 반영한다. 결정형 조사와 비싼 원본 evidence만 research 규칙에 따라 보존한다. 자동 실행은 권위 문서들을 바꾸지 않고 리뷰 요청에서 멈춘다.

## 유지한 경계

- 업스트림 원문을 복사하거나 자동 merge하지 않는다. 흡수 대상은 사상이다.
- 로컬 클론은 fetch로 비교할 수 있지만 merge/pull하지 않는다.
- tracking point는 실제 리뷰가 끝난 뒤에만 갱신한다.
- 모델·도구가 발전해 사라진 scaffolding도 중요한 변화로 취급한다. 새 기능 추가만 후보가 아니다.

## 변화의 계보

- P-0001의 업스트림 비교와 gstack User Challenge가 기본 검토 태도를 만들었다.
- P-0013은 검토 입력을 영구 지식으로 비축하지 않고 결론을 권위 원천에 직접 반영하도록 했다. P-0025는 이 원칙을 유지하면서 전용 digest 폴더와 packet 절차를 제거했다.
- 2026-07-26 승격 때 2~3주 변화 감지, minor 이상 gate, 자동 실행의 정지선을 확정했다.
- P-0022는 Align의 질문을 비교 가능한 round로 바꾸었고, 같은 이유로 후보 리뷰도 관련 항목을 묶을 수 있게 했다.
