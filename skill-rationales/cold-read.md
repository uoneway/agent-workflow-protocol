# cold-read — 한국어 의사결정 기록

> **상태:** 확정됨. 실행 기준은 [`skills/cold-read/SKILL.md`](../skills/cold-read/SKILL.md)다.

Cold-read는 대화 맥락이 없는 실행자가 작업 계약만으로 시작할 수 있는지 보는 조건부 감사다. 다음 실행자가 실제로 읽을 문서와 연결된 원천을 함께 주고, 시작 차단·후속 차단·사소함으로 질문을 분류한다.

P-0002는 superpowers의 adversarial spec review에서 fresh-reader 검증을 가져왔다. P-0017은 초안이 존재하면 크기와 무관하게 항상 감사하도록 했다. P-0022는 이 결정을 좁혔다. 별도 agent의 토큰뿐 아니라 감사 때문에 늘어나는 설명 사본, 사용자 질문과 실행 지연도 비용이다.

현재 트리거는 실제 context handoff, 높은 모호함 비용, 자기평가 편향 위험, 반복된 handoff 실패, 사용자 요청이다. 감사 질문을 닫기 위해 코드·진행 상태·명령을 문서에 복사하지 않는다. 권위 원천을 보게 하거나 코드 밖 의도만 추가한다.

이 감사는 빠진 질문을 찾지만 틀린 사실을 찾지는 못한다. 실제 실행자는 여전히 권위 원천과 산출물을 검증해야 한다.

P-0029는 시작 차단을 합의 범위에서 안전한 첫 행동을 고를 수 없는 누락으로 좁혔다. 실행 중 확인할 사실은 그 자체로 차단이 아니다. 독립 agent가 없으면 미수행을 밝히며 자기 점검을 독립 감사 통과로 대체하지 않는다. 합의나 정책상 필수 감사인 handoff만 보류하고 독립적인 작업은 계속한다.
