# setup-workflow — rationale

## 현재 역할

`setup-workflow`는 Agent Workflow Protocol을 대상 레포에 적용하거나 갱신한다. 각인은 `AGENTS.md`의 관리 마커 블록 하나를 기본으로 하며, 제품 방향이 코드 밖에 있을 때만 `VISION.md` 또는 동등한 기존 기준 문서를 권위 원천으로 둔다. 이슈 트래커가 없고 실제 미착수 후보가 있을 때만 `BACKLOG.md`를 만든다.

setup의 목적은 프로젝트 설명 문서 묶음을 미리 만드는 것이 아니다. `orient`가 live source와 보존된 의도를 조합해 현재 설명을 만들 수 있도록, 코드 밖에 남아야 할 진실과 스킬 라우팅만 정리하는 것이다.

## 선택과 경계

- 마커 안은 `setup-workflow`가 관리하고 밖은 레포가 소유한다. 갱신 전에 저장된 SHA-256과 실제 본문을 비교해 사용자 수정을 감지하며, 불일치·중복·고아 마커를 임의 복구하지 않는다.
- 기존 문서의 의미 분류는 스크립트가 아니라 agent가 한다. 스크립트는 git·마커·파일·도구·머신 선택처럼 결정적으로 관찰할 수 있는 사실만 JSON으로 낸다.
- 문서 삭제와 고유 진실 이동은 brownfield 이식에 묵시적으로 포함되지 않는다. 후보와 권위 이동안을 제시하고 사용자가 승인한 범위만 바꾼다.
- 머신 전역 라우팅은 최초 선택을 기억하지만 레포 로컬 마커가 항상 우선한다. 유효한 선택은 반복 질문하지 않으며, 사용자가 재설정을 요청하면 다시 연다.
- setup 여부는 다른 스킬의 hard dependency가 아니다. 레포 각인은 협업자와 미래 세션에 지속 규칙을 전달하지만, 개별 스킬 호출을 막는 설치 게이트가 아니다.

## 방향 변화

초기 설계는 6단계 워크플로우, 수기 `PROJECT_STATE`, 전역 결정 연번, 기본 문서 골격을 함께 이식했다. P-0020~P-0022에서 현재 상태의 권위를 live source로 옮기고 문서 생성을 실제 필요가 생길 때로 늦추면서, setup도 최소 각인 방식으로 다시 설계했다. P-0025는 전용 draft·review packet 체계를 제거했고, P-0026에서 영어 실행본과 동봉 자산을 forward test한 뒤 확정했다.

이식 메커니즘 조사의 결론과 출처별 채택·기각 기록은 `upstream-sources.md`에 남아 있다. 특히 마커 소유권, 결정적 pre-flight, lazy 생성, 갱신 시 사용자 편집 보존을 가져왔고, 대형 설치기·코드베이스 설명 역생성·setup hard dependency는 채택하지 않았다.
