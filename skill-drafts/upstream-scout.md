# upstream-scout — 초안

베이스: 2026-07-07 세션에서 수동으로 수행한 방법론 그 자체 (superpowers·gstack·mattpocock 병렬 분석). 참조: mattpocock의 changelog 관행(다이제스트를 산출물로), gstack `learn`(관찰→학습 승격 루프). 호출 방식: user-invoked (또는 주기 실행).

```yaml
name: upstream-scout
description: 참조하는 공개 스킬 레포·블로그의 변경을 수집해 내 워크플로우에 흡수할지 검토할 때. 사용자가 "업스트림 확인하자", "upstream-scout 돌려줘"라고 하거나 정기 리뷰 시점에 사용.
```

## 본문

**1. SOURCES 읽기.** `upstream-sources.md`에서 추적 대상과 마지막 리뷰 지점을 읽어라.

```md
# Upstream Sources
| 소스 | 종류 | 마지막 리뷰 | 지점 |
|---|---|---|---|
| mattpocock/skills | repo | 2026-07-07 | commit abc1234 (v1.0.1) |
| aihero.dev | blog | 2026-07-07 | "Real-world feature build" |
| obra/superpowers | repo | 2026-07-07 | v5.0.7 |
| garrytan/gstack | repo(로컬 클론) | 2026-07-07 | v1.58.5 |
```

> `[신규 · 세션 합의]` "마지막 리뷰 커밋에서 diff해야 주기 실행이 의미 있다" — 출처 추적. 첫 실행 시 이 파일이 없으면 위 표(2026-07-07 세션 결과)로 생성.
> `[검토점 1]` 파일 위치: `link-workflow/upstream-sources.md`(프로토콜 옆) vs 스킬 폴더 안. 프로토콜 옆이 맞아 보임 — 스킬은 절차, 상태는 문서.

**2. 병렬 수집.** 소스마다 background agent 하나씩 띄워라. 각 agent의 임무: 마지막 리뷰 지점 이후의 변경(커밋 diff, 새 스킬, 새 글)을 수집하고 아래 프레임으로 보고하라 —

- 무엇이 바뀌었나 (사실)
- 어떤 사상의 이동인가 (해석)
- 우리 프로토콜·스킬의 어느 부분에 영향 가능한가 (접점)
- 우리에게 없는 새 아이디어 top 3 (각 한 줄 근거)

> `[신규 · 2026-07-07 세션]` 세션에서 쓴 9차원 프레임의 압축판. 첫 전수 분석은 9차원이 맞지만 증분 리뷰는 4항목이면 충분 — 다이제스트가 무거우면 리뷰를 미루게 되고, 미루면 루프가 죽는다.
> `[검토점 2]` 로컬 클론(gstack)은 fetch만 하고 merge/pull 금지 — agent 지시에 명시할 것.

**3. 다이제스트 착지.** 수집 결과를 하나로 종합해 `docs/_research/YYYY-MM-DD-upstream-digest.md`로 저장하라 (개인 워크플로우 repo 기준으로는 `link-workflow/digests/`). 소스별 섹션 + 맨 위에 "채택 후보" 목록.

> `[검토점 3]` 착지 위치 — 이 스킬은 특정 프로젝트가 아니라 워크플로우 자체에 대한 리서치라서 `docs/_research/` 관례가 안 맞을 수 있음. link-workflow 폴더에 digests/를 둘지 결정 필요.

**4. 검토 세션.** 사용자와 채택 후보를 하나씩: 이것이 우리 원칙과 충돌하는가, 보완하는가? 전제 도전과 같은 규격 — 기존 프로토콜이 기본값이고, 변경을 제안하려면 "우리가 놓친 것 + 안 바꿨을 때의 비용"으로 입증하라.

> `[가져옴 · 프로토콜 §2 전제 도전]` 같은 규격의 재사용(원 출처는 gstack User Challenge — `upstream-sources.md`의 garrytan/gstack 항목 참고). 대상이 "사용자의 방향" 대신 "기존 프로토콜"일 뿐.

**5. 기록.** 채택분은 AGENT_WORKFLOW_PROTOCOL.md 반영 + 변경 이력 테이블에 사유와 함께. 기각분도 변경 이력에 남겨라 — 다음 스카우트가 같은 아이디어를 다시 올리지 않도록. 끝나면 `upstream-sources.md`의 리뷰 지점을 갱신하라.

> `[신규]` 기각 기록 — decision-log의 "조용한 재론 방지"를 이 루프에 적용. 2026-07-07 변경 이력에 기각분(accretion 등)을 남긴 것과 같은 패턴.

## 금지

- 업스트림 텍스트를 자동 merge하거나 복붙하지 마라. 흡수 대상은 사상이지 텍스트가 아니다.
- 다이제스트 없이 곧바로 프로토콜을 수정하지 마라 — 수집과 채택 사이에 반드시 사용자 검토가 있다.

> `[신규 · 세션 합의]` 이 스킬의 존재 이유이자 경계. mattpocock의 "문서 부패" 관점에서도: 남의 문서를 복붙하면 남의 doc rot을 수입한다.

> `[검토점 4]` 주기 — friction-log 리뷰(2~3주)와 묶어 같은 세션에서 할지, 별도 주기(월 1회?)로 둘지. 묶으면 "내 마찰"과 "남의 진화"를 같은 자리에서 비교하는 시너지가 있음.
