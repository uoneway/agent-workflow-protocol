## Agent Workflow

원문: https://github.com/uoneway/agent-workflow-protocol/blob/main/AGENT_WORKFLOW_PROTOCOL.md

- 흐름은 Orient → Align → Act → Reorient다. 매 요청마다 별도 단계나 승인을 요구하지 않으며, 열린 가지의 capture는 어느 단계에서나 한다.
- 현재 사실은 다음 판단에 필요한 코드·테스트·git·worktree·PR·issue·session 같은 live source에서 읽는다. 다음 행동과 중요한 미확인 사항을 설명할 수 있으면 탐색을 마치며, 수기 상태표에 복제하지 않는다.
- 문서는 다른 신뢰 가능한 원천에서 복원할 수 없는 제품 의도·경계·비싼 결정·외부 증거만 보존한다.
- 결정에 쓰인 리서치는 짧은 synthesis와 참조 원문 목록을 남긴다. 휘발성·재수집 비용·정확성·재해석 가치가 큰 원본 evidence는 기본 읽기 경로 밖에 보존한다.
- 한 세션에서 이어지는 작업은 대화의 합의로 충분하다. 다른 session·agent·사람·worktree로 넘길 때만 짧은 작업 계약을 issue 또는 임시 workstream에 남긴다.
- 현재 요청과 이전 합의의 결과·경계·위임을 인정한다. 실행 요청은 합의된 범위의 탐색·구현·검증·정리까지 이어가고, 상담·리뷰 요청은 근거 있는 답변으로 마친다.
- 제품 취향·중요한 불확실성은 위임 여부를, 외부 작용·비용·사용자 권한은 기존 승인 범위를 확인한다. 새 판단이나 권한이 필요한 부분만 묻고 독립적인 작업은 계속한다.
- 검증은 변경 동작·실패 영향·레포 필수 검사에 맞춘다. 필요한 검증이 통과하면 새로운 변경·실패·미해결 위험 없이 확대하거나 반복하지 않는다.
- 지침 때문에 멈출 때는 근거 문서·문구와 필요한 판단을 밝히고, 명시적 요구와 자신의 해석을 구분한다.
- `orient`는 상황 파악, `align`은 다음 행동의 합의에 쓴다. 외부 사실 조사는 `workflow-research`, 독립 감사가 실제로 필요할 때는 `cold-read`를 쓴다.
- 작업 중 새 가지는 쫓지 않는다(park). 코드 밖에 남지 않으면 사라질 비싼 정보만 기록한다(mark). 사람의 판단 시점에는 현재 원천에서 설명한다(explain).
- 사람이 내릴 판단이 남았으면 그것부터, 없으면 결과와 실제 검증부터 설명한다. 판단을 바꾸는 주장은 원천과 확인 방식(실행·읽기·추정)을 밝힌다. 텍스트로 판단하기 어려울 때만 표·다이어그램·HTML 같은 매체를 쓴다. 목표·동작·중요 경계가 바뀌면 해당 부분만 다시 Align한다.
