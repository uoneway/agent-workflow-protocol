# Field Notes — 실적용 회차 기록

link-workflow의 프로토콜과 스킬을 실제 서비스 레포에 적용하는 동안만 두는 회차별 **review packet**.

모든 작업에 회차 문서를 만들지는 않는다. `field-notes/`는 프로토콜이나 스킬을 실제로 검증한 **의미 있는 round**에만 남긴다. 맥락이 더 필요 없는 운영 마찰은 `protocol-friction-log.md` 한 줄로 충분하다. 리뷰가 끝나면 확정·기각의 이유만 권위 문서에 남기고 이 디렉터리의 회차 문서는 삭제한다.

각 파일은 한 회차(round)의 실행 로그다. 목적은 두 가지다.

1. **플로우 검증** — 프로토콜과 스킬이 실제 작업에서 어떻게 동작했는가. 어디서 막혔고, 어디가 비어 있었는가.
2. **개선 판단 지원** — 회고에서 나온 판단이 어떤 실제 상황에서 나왔는지 리뷰 세션이 확인한다. 결론 그 자체는 이곳이 아니라 권위 문서에 남긴다.

## 파일명

`<repo>-round-NN-<slug>.md`

## 회차 문서의 구조

- **Round 목표** — 이 회차에서 서비스와 플로우 각각에 무엇을 달성하려 했는가
- **실행 로그** — 어떤 스킬을 어떤 순서로 썼고 무엇이 나왔는가
- **마찰** — 실행 중 마주친 어색·공백·반복·위반. 각 항목은 `protocol-friction-log.md`에도 한 줄로 남긴다
- **회고** — 마찰의 원인과 처리 경로 판단
- **다음 회차로 넘기는 것** — 확정 변경, 보류 항목

## 마찰 로그와의 관계

`protocol-friction-log.md`는 **한 줄 캡처**의 장소이고, 여기는 **그 한 줄이 나온 맥락**의 장소다. 리뷰 세션은 로그를 클러스터링한 뒤, 판단이 필요한 항목만 여기로 내려와 맥락을 확인한다.

회차 문서에 마찰의 원인 분석을 적는 것은 허용된다 — 회차 문서 자체가 회고 산출물이기 때문이다. 캡처 시점의 무해석 원칙은 `protocol-friction-log.md`에만 적용된다.

## 진행 중인 회차

없다.

회차가 열리면 여기에 레포·회차·검증한 스킬·마찰 건수를 한 줄로 적고, 리뷰가 끝나면 그 줄과 회차 문서를 함께 지운다. 완료된 회차의 목록을 여기 쌓지 않는다 — 회차가 만든 결론은 프로토콜 변경 이력·스킬 rationale·`upstream-sources.md`가 들고 있고, 회차 자체의 이력은 git이 안다.
